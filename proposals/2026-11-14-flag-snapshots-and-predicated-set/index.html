    A flag is a snapshot, and SLEIGH's temporary flags are flags¶

    Filled from docs/templates/DECOMPILER_CHANGE_PROPOSAL.md.

    1. Baseline¶

    Thumb subs r0, #0; it ne; movne r0, #1 is how a Cortex-M compiler returns a boolean. Fission printed the predicate as a branch on a named flag and kept the flag writes inside it:

    uint isSomeStatEnabled(void)          // betaflight_STM32F405, -O2
{
    r0 = *(uint *)(tmp_8052aa4 + 20);
    tmpzr = r0 == 0;
    if (!tmpzr) {
        r0 = 1;
        tmpzr = tmpov;
    }
    return r0;
}

    Measured on the full inlined (-O2) DecBench config, 26,012 functions, on main at 1c10edab0:

    functions
    mention tmpng / tmpzr / tmpcy / tmpov 1,511
    branch on one of them 664

    They sit in nine projects (betaflight 496, crazyflie 330, cleanflight 248, u-boot 220, libopencm3 112, chibios 44, nuttx 39, freertos 15, riot-os 7). The shape is not an optimisation artefact: an earlier unoptimized (-O0) run of the same pipeline has it in 9,027 of 33,868 functions across eight projects.

    Ranked by excess structure distance over Kuna on that config, the predicated if was the largest single class (12.6x).

    2. Owner¶

    Normalize, in three places, found in this order.

    1. recovery/flag_recovery.rs::flag_family. ARM's SLEIGH computes the condition codes into tmpNG/tmpZR/tmpCY/tmpOV and copies them into NG/ZR/CY/OV only for the flag-setting forms. The family listed the architectural names and not the temporaries, so neither the substitution of a flag into its condition nor the dead-flag cleanup looked at them.
    2. arith/conditional_move.rs, the default/override merge. With the flag gone the body is x = d; if (x != 0) x = 1;. The merge turned every x = d; if (c) x = o; into x = c ? o : d, which evaluates c before the default is stored. When c or o reads x that is a different program. It was already wrong on main, on x86:
    rax = rax ? rax + 1 : strrchr(param_1, 47);     // sysvinit `mybasename`
    1. recovery/flag_recovery.rs, the substitution itself. Reading the changed output of (1) turned up a condition that tested a register the previous statement had just replaced. The walk records flag -> defining expression and substitutes the expression at each later use; nothing removed a record when one of the expression's operands was written. The same hole was open for zr and the x86 flags before this change:
    r12 += param_2;
if (__scarry(r12, param_2)) {                   // coreutils `dd`, on main

    (1) would have widened it to roughly 3,000 more flag writes, so it is fixed first.

    3. Invariant¶

    • A flag definition is a snapshot. Substituting its expression at a use re-evaluates it there. That is the flag's value only while nothing the expression reads has been written: not a variable it names, not memory if it loads, not the flag itself on some path. A statement list containing a label can be entered without passing the definition at all. A loop body and a switch arm can run after themselves, so what they write is in effect at their own entry. A definition that calls is not re-evaluated.
    • The whole-function single-definition fallback has no position, so it takes only definitions that read nothing the function ever assigns.
    • x = d; if (c) x = o; is x = c ? o : d only when the reordering is invisible: c and o do not read x, d has no effect to lose, and c has none that could change what d reads.
    • x = d; if (x != 0) x = 1; is x = (d != 0). d is still evaluated exactly once, so this needs none of the above.
    • A flag is scratch. An instruction writes it whether or not anything tests it; its value matters only where something observable reads it. A flag an instruction carries through itself (of = keep ? of : new) has a reader for every write and no test. The unsound substitution used to break such cycles by accident; cleanup/scratch_liveness.rs already retires closed cycles by reachability from observable roots, and now counts flag variables among the names it may retire.

    ISA-agnostic check (ADR 0009):

    • [x] No condition on an ISA enum. The only ISA data is four more register names in the flag family; the rules are def-use and evaluation-order facts.
    • [x] The synthetic tests state statement shapes, not a compiler tuple.

    Comparable coverage: the snapshot rule is exercised on ARM (tmpzr, zr) and x86 (cf, of, zf) rows of the same sweep; the default/override rule on x86-64 (strrchr, fileno chains) and Thumb.

    4. Risk and ownership¶

    • Existing owners extended; no new pass. collect_written_vars (conditional_const), expr_reads_memory / stmt_may_write_memory (condexe) and collect_address_taken_locals (defuse) are reused rather than restated.
    • Shared substrate: def-use / reaching-definition fact.
    • Interaction: a flag that can no longer be substituted stays a named boolean (of = __scarry(a, b); a += b; if (of)). That is the cost of the snapshot rule and it is the correct program.
    • Telemetry: none.
    • Not addressed, seen while reading output:
    • cleanup_after_constant_folding_init drops a stack store that is read only through the address of its neighbour (buf[1] of a two-byte buffer passed as &buf[0]). It runs only when constant folding changed something; with the temporary flags gone it runs less often, so some of those stores now survive. That is a side effect, not a fix.
    • Two predicates on one compare that write the same register (movne r0, #1; moveq r0, #0) keep the flag as a variable instead of becoming one if/else.
    • A dead default/override pair directly followed by the select that recomputes it: 9 occurrences in the sweep, 2 before.
    • tail_dup duplicates a tail that contains a branch. Removing the dead flag writes brought more ARM tails under its six-statement limit (see the unoptimized rows in section 5). A limit on what a duplicated tail may contain is a separate change with its own measurement.
    • An unsigned compare moved into a loop condition prints without its (uint) cast (while (i < 10) for an int i compared unsigned). The cast-restoring pass skips loop conditions and stops at the first statement it changes; both are on main and are fixed separately.

    The largest family among the rows that got worse is return-tail duplication (18 rows, +392; one function goes 20 -> 120). tail_dup copies a label's tail into each jump when the tail is at most six statements. In the function traced pass by pass, main's tail held four dead flag assignments and was nine statements long, so the rule did not fire; with them gone it is four statements and is copied into six arms, if included. The pass is untouched here and already behaves this way on x86.

    The reason the output is better without the metric: the old text tested a value on the far side of the write that changed it, and named registers the machine never tests.
