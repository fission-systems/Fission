    Piece statements, and three places that were wrong behind them¶

    Date: 2026-11-18. Status: implemented and measured -- see section 5 for what the measurement does and does not support. Filled from docs/templates/DECOMPILER_CHANGE_PROPOSAL.md. Third of three on one branch, after the dominating-write change and the plan-acceptance change.

    1. Baseline Row Anchor¶

    The plan-acceptance change lost 50 structure-perfect -O0 rows. Thirty were one shape, read on the full local DecBench unoptimized config:

    function binaries before after the plan was accepted
    log_level_name, log_facility_name 12 openssh each while (tbl[i].name) { if (..) return ..; i++; }, 16 lines 55 lines, the header copied to the entry and the latch, a label and a goto
    fmt_multistate_int, lookup_opcode_name 3 each same same

    Fixing that exposed three older defects, all read on real functions:

    function config what is printed what the binary does
    tar 0x1f625, tar 0x20b9f -O0 p->field_10 = (uchar)rax and p->field_8 = param_2 are absent stores them
    sshd 0x42b21 -O0 the \|= 4096 store after a list walk is absent stores it
    bash _rl_nchars_available, mirai util_local_addr, openssh ssh_krl_file_contains_key -O0 uint *slot_0 = (uint *)local_14; .. __errno_location(); *slot_0 = 0; *__errno_location() = 0
    libedit history_def_curr, bash uconvert, bash bash_complete_filename_internal -O0, -O0, -O2 if (c <= 0) { rdx = 5; } *ev = rdx; -- the other arm's rdx = 8 is absent assigns on both paths
    • Failure category: a loop not recovered; stores deleted; a write through a pointer computed once from the wrong value; one arm of a branch dropped.

    Why the output is wrong, without a metric: it omits writes the program makes and writes errno through an uninitialized local.

    2. Owner Proof¶

    • [x] Builder/materialize: materialize/mod.rs, lower_block_ops_range.
    • [x] Normalize: global_opt/dead_store.rs, memory/slots.rs.

    • [x] Structuring host: structuring/linear/mod.rs, is_trivial_forwarding_block.

    • The wrapper. An op whose output the emission plan names in pieces (rax = zext(eax) is two 4-byte storages) lowers to several assignments, returned as one PreHirStmt::Block because the caller takes one statement per op. The pre-structuring passes that fold a temporary into its one reader do not look inside it, so a loop header kept three assignments its condition would have held, and the header was then copied. Experiment on log_level_name: unwrapping alone gives the 16-line while; relaxing the plan's TempPreserved bindings alone changes nothing.

    • Dead store elimination. FISSION_NORM_DUMP-style pass tracing on sshd 0x42b21: the store *(local_8_3 + 4) = rdx | x is present before dead_store_elimination and absent after. classify_base_object (memory/partition.rs) classes any Var whose name starts local_ as the stack slot. Here local_8_3 is a variable holding a pointer.
    • Slot aliases. collect_single_var_aliases counted an assignment only when its right side was a variable, so p = q followed by p = p + 16 in a loop left p "an alias of q"; the alias slot_4 = q + 4 is a declaration initializer, evaluated once. With that corrected the base stays p, which is_surface_stable_slot_display_base accepts by name and which the initializer would read before the body assigns it.
    • Forwarding blocks. Found by reading the lost perfects of the first sweep of (1)-(3). history_def_curr's builder output has rdx = 8 in one arm block and rdx = 5 in the other; the structured body has only the second. The arm is a copy, an extension and a branch, which is_trivial_forwarding_block classes by opcode as a block nothing is printed for, and conditionals/short_circuit.rs then steps over it. That is true of the legacy path, where a copy's reader looks the value up, and false under the plan, where the copy is the assignment.

    3. Generality / Invariant Proof¶

    (a) Statements an op lowers to are statements of its block.
(b) A name the function assigns is a variable. A write through it goes where
    its value points, not to the slot the name came from.
(c) An alias of a variable is a name assigned exactly once, by a copy.
(d) A declaration's initializer runs before the body, so it may read no name
    the body assigns.
(e) A block that makes an assignment the plan emits is not a block that
    merely forwards.
    • [x] No ISA, calling convention, function or address appears in any of them.
    • [x] Synthetic tests state the statement shape only.

    Shape repeats: (a) thirty rows in two optimisation-independent table-search functions plus the sample below; (b) 151 more store statements on the -O0 sample and 9 on -O2; (c)/(d) declaration-initialized slot_N pointers fall 3,648 -> 3,334 (-O0) and 794 -> 680 (-O2) on the sample.

    4. Risk And Ownership Check¶

    • No new pass, metric or dependency. One shared helper, collect_assigned_names, in analysis/defuse.rs.
    • (b) only withholds a deletion and (c)/(d) only withhold a rewrite; neither can remove code. What they can cost is a store that really was dead, or a slot alias that was sound, staying as plain pointer arithmetic.
    • (b) is applied in the pass that deletes, not in classify_base_object, which also feeds memory heritage. The same misclassification is still there for that consumer; it is not known to print anything wrong.

    Change (4) alone, measured as the difference between two sweeps that differ only in it: 14 -O0 texts changed (10 better, -67; 3 worse, +12; 4 new perfects) and 5 -O2 texts (2 worse, +6). The three worse rows that were read (normalize_filename_x, uconvert, bash_complete_filename_internal) each gained the arm that had been dropped.

    Read, not inferred:

    • The thirty table-search rows are perfect again.
    • The 24 -O0 perfects still lost: sixteen at GED 6 are the a == 13 || a == 1 returns that were scored perfect while reading an unassigned temporary (dev_ino_compare read here, is_directory and perm_related_errno on the previous sweep; the rest by name only); ssh_krl_file_contains_key (five binaries) and util_local_addr used the wrong errno pointer and now use the right one with the two returns merged into one; u32tochar has its terminating store and return copied into three branches where it had one join -- a structural loss on output that was right before; make_cond_command was not read.
    • No row lost a real callee against the baseline. The names that disappear are flag intrinsics (__carry, __scarry, __sborrow, __popcount).
    • -O2 distance is up 0.55% over the baseline with perfect up by one. The rows read from the worse side of the first two sweeps were restored code (sshkey_drop_cert: every case had lost its assignment); of the worse rows of this last step, most were already at or over the source's node count and grew, which is that same pattern, and they were not individually read.

    What this supports. At -O0 every measure moved the right way against the baseline -- distance, perfect, Union, type -- and the lost perfects that were read are corrections but for one. At -O2 the distance is worse and the perfect count flat; the explanation read on the largest rows is code that used to be deleted, and that explanation was not checked on every row.

    7. Review Notes¶

    • Not fixed and seen on the way: sshd 0x42b21's loop is still a label and a goto. u32tochar (above). The emission path is still more verbose than the legacy path on straight-line code (uVar0 = rsi - 1; rsi = (uint)uVar0;), because the low piece of an IntZExt is not coalesced with its source. classify_base_object's name-based stack class still feeds memory heritage. The stale select on call-clobbered registers (tar lseek_or_error) is untouched.
