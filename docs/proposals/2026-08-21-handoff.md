# Handoff

State of the DecBench work as of `21ff7ca3e`. Written to be picked up cold.

## Where things stand

`main` is clean and pushed. Fission last scored **#8-9 of 12, Union 22.4%
(56/250)**, on submission `v0.2.1`; nothing since has been re-submitted, so the
board does not yet reflect any of the work below.

Every claim here is measured, and the measurements live in the proposals listed
at the end. Where a measurement was later invalidated, that is recorded too.

## The one rule that matters most

`AGENTS.md` gained a section this cycle -- "Fitting the metric instead of the
row". The Pass-Gate Lint catches `func_name ==` and `addr == 0x...`, which is
the only form of overfitting a static scan can catch. The form that has
actually cost this project contains no benchmark identity and passes every
scan: **optimising a metric along an axis the metric cannot see.**

> State why the new output is better without mentioning the metric. If the
> sentence cannot be written, the change is fitting the metric, not fixing a
> defect.

It has bitten twice. Goto density once scored a structuring that replaced 38
transfers with 2,743 short-circuit operators as a clean win. And this cycle's
own frame-size fix *cost* two functions on the type metric and was kept anyway,
because "we reported a zero-size frame for a function with six pushes" passes
the test and the metric's opinion does not.

## Do not re-derive these

Four ideas were closed with measurement and no production code. Each could
have consumed a cycle.

- **Version-tolerant function identification** is declined. Seeding from
  string references reaches 15.5% and propagation stalls at 18-23%, against a
  pre-registered bar of 60%. `2026-08-20-version-tolerant-function-identification.md`
- **Recompilation as a type oracle** is declined. The compiler does react to
  types, 5-73% of a function's instructions, but of 17 suggestions none
  improved the type metric and four made it worse.
  `2026-08-21-recompilation-as-a-type-oracle.md`
- **Assert strings for variable names** is declined on yield: 16 of 150 scored
  binaries carry any, giving 49 identifiers corpus-wide.
- **Further FID investment** is declined. Glaurung ships 30 signatures and
  places #3; Ghidra's default distribution ships none and places #8; Fission
  ships 1.83M and places #8-9. Library identification does not appear to drive
  standing.

## Corpus choice decides what you learn

- `corpus/scale` -- 258 programs at `-O0` and `-O2-noinline`, with symbols,
  with published source CFGs for 64,231 functions. **Right for structure**, and
  97% of those score on exact GED rather than the approximation.
- **Wrong for types**: it scores 37% type-perfect against DecBench's 3.8%, ten
  times easier, because `-O0`-with-symbols puts every variable in a predictable
  stack slot.
- `corpus/dev` -- 198 binaries, gcc and clang, `-O0`/`-O1`/`-O2`, DWARF at every
  level, no symbol table. **Right for types**, and the only local split that
  separates `-O0` from `-O2`.
- Neither is the scored sample-set, which is the point.

## Check the scorer's HEAD before quoting a number from it

`vendor/decbench` sat sixteen days behind while four metric changes landed
upstream, two of which altered what a score means. It is now at `d9f4f8a`.
`GED_MAX_NODES` went 60 -> 200 with an isomorphism short-circuit, so "above 60
nodes the score is a size delta" is no longer true. And note
`fission-benchmark/runner/type_match.py` is a **fork, 1,222 diff lines from
upstream** -- this cycle's type percentages came from an implementation that
does not score us.

## Open threads, with their starting points

1. **Types, the winnable half.** `-O2` loses 45% of variables to registers the
   ground truth discards -- unwinnable for Ghidra and Glaurung too. The
   addressable loss is `-O0`'s 22% found-and-mistyped, and the census is done:
   nearly half is width alone (`int` -> `longlong` 20 times, `size_t` -> `uint`
   12), then pointers printed as integers (`char*` -> `ulonglong` 8). 57 of the
   125 are function arguments. `2026-08-21-type-metric-where-it-is-winnable.md`

2. **`local_X` naming is coupled to the type metric.** `_effective_offset`
   parses the hex out of our variable names and calibrates a per-function shift
   against DWARF. Any further slot-naming work must be measured against types,
   not only against duplicate slots. `2026-08-21-frame-size-from-pcode.md`

3. **`asm_mnemonic` carries p-code opcode names, not disassembly.**
   `resolve_stack_address_from_memory_op` searches it for `[` and fails
   silently, falling back to varnode resolution. How much stack addressing that
   loses has never been measured. Changing the field would also touch
   `tail_wrapper`, which depends on the literal `"INSN_RAW"`.
   `2026-08-21-prologue-scan-reads-pcode-names.md`

4. **102 duplicate stack slots remain**, down from 214. Whether they are real
   distinct storage or a residual naming artifact is unmeasured.

5. **The nightly `CI Heavy Validation` has failed every night since 2026-08-13**,
   predating all of this. Unrelated and unexamined.

6. **A report to the DecBench maintainer was drafted and withheld.**
   `type_match._get_location` keeps only `DW_OP_fbreg` and discards every
   register form, which makes 79% of `-O2` ground-truth variables unreachable
   for every tool. The docstring shows this is deliberate, so the draft's
   framing as an oversight is wrong; what is worth sending is a proposal to
   carry the register number and add a matching pass. Repo is
   `github.com/Noelo-Lab/decbench`, issues open.

## Baselines a newcomer will trip over

- `cargo nextest run --workspace` has **7 pre-existing `fission-emulator`
  failures** plus a `fission-dir::phase2_corpus_ground_truth` timeout. Verified
  pre-existing by stashing. Anything beyond that is yours.
- The DecBench sample-set sweep occasionally reports one decompile failure that
  does not reproduce -- a timeout under eight-way parallel load, not a
  regression. Re-run before believing it.
- Local `gcc` is Apple clang; there is no real gcc and no Docker on this
  machine, so recompilation rates are **not** comparable to the benchmark's.
  Cross-compiling to `x86_64-unknown-linux-gnu` with clang does work for
  object-level comparison.

## A pattern worth carrying forward

Five times this cycle a test was found asserting on something other than its
subject: two on unreachable code, two on a signature's `undefined` return while
being named for parameter aliases, and seven fixtures modelling `push` as its
`Copy` half alone -- a shape the pipeline never produces, which passed only
because the scan under test read the label instead of the p-code.

Pinning whole rendered output with `contains` freezes things the test was never
about. Every one of these was found by a change that was *correct*, and each
would have looked like a regression to anyone trusting the test.
