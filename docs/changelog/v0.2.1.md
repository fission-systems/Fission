# Fission v0.2.1

Fission 0.2.1 is a **release-integrity** patch. It contains no decompiler
changes: v0.2.0's code is unchanged here. What it fixes is that v0.2.0 shipped
against resource data that never reached a released artifact, and two
dependency advisories that had been failing CI.

If you are installing Fission, use this release rather than v0.2.0 — several
v0.2.0 features are inert in v0.2.0's own artifacts, for the reason below.

Tagged commit: `3b4d4e1a2`
Release: https://github.com/fission-systems/Fission/releases/tag/v0.2.1

## Release summary

| Area | v0.2.0 | v0.2.1 |
| --- | --- | --- |
| `utils/` bundle in release artifacts | `assets-v2`, published 2026-08-10 — predates the entire v0.2.0 signature corpus | `assets-v3`, built from the v0.2.0 tree; a strict superset of v2 plus the 30 files v0.2.0's code depends on |
| PE ordinal imports, non-x86 patterns, GDT/phnt/Rust/WDK type corpora | code shipped, data absent from the artifact | data present |
| `webbrowser` | 1.2.1 — RUSTSEC-2026-0257, argument injection through `BROWSER` | 1.2.4 |
| `lru` | 0.16 — RUSTSEC-2026-0253, use-after-free in `LruCache::pop()` | 0.18.2 |
| CI on `main` | red on every code commit since 2026-08-11 | green, L0 and L1 |

## Why v0.2.0's artifacts were incomplete

`utils/` is gitignored. Both CI and CD materialize it by downloading
`fission-utils.tar.gz` from a long-lived `assets-v*` release pin, and that pin
was `assets-v2`, published 2026-08-10 — before any of the v0.2.0 signature
work landed. Nothing in the pipeline noticed, because nothing compares the
pinned bundle against what the tree's code expects to load.

Diffing the published bundle against the authoring tree found 30 files, 34 MB,
present locally and absent from `assets-v2`:

| Missing from the artifact | v0.2.0 feature it backs |
| --- | --- |
| `signatures/ordinals/{x86,arm}_ordinals.json` | PE ordinal import resolution |
| `signatures/patterns/ghidra/*_patterns.xml` (22 files) | function-start patterns for non-x86 architectures |
| `signatures/typeinfo/{generic,mac_10.9,win32}/*_structures.json` | GDT-mined structs |
| `signatures/typeinfo/rust/rust_structures.json` | Rust struct layouts |
| `signatures/typeinfo/win32/phnt_structures.json` | phnt NT structs |
| `signatures/typeinfo/win32/wdk_signatures.txt` | WDK kernel API signatures |

This is also why CI had been red on every code commit since 2026-08-11: five
tests assert that data is loadable, and on a runner it was not there. The
failure was read as flakiness and not chased down before v0.2.0 was tagged.

`publish-utils-assets.yml` could not fix this on its own — it bootstraps from
the existing pin, so it can only republish what is already published.
`assets-v3` was therefore uploaded from the authoring tree, after verifying
that tree is a strict superset of the v2 bundle (nothing is dropped). It also
excludes the macOS AppleDouble (`._*`) entries that had inflated the v2
tarball's file count to 7,138 against 3,468 real files, and its `.slaspec`
count to 292 against 146 real specs.

The pin moved to `assets-v3` in `setup-utils`, `reusable-cli-smoke`,
`reusable-nir-check`, and `publish-utils-assets`.

## Dependency advisories

Two had fixes and got them:

- **`webbrowser` 1.2.1 → 1.2.4** — RUSTSEC-2026-0257, a real vulnerability. On
  Unix the caller-supplied URL was substituted into the `BROWSER` template
  *before* the result was tokenized with `split_ascii_whitespace()`, so a URL
  that retains spaces became additional browser arguments. Reported upstream
  with a Chromium reproduction injecting `--remote-debugging-port` (exposing a
  local DevTools endpoint) and `--proxy-server`.
- **`lru` 0.16 → 0.18.2** — RUSTSEC-2026-0253, potential use-after-free from
  missing panic safety in `LruCache::pop()`. The fix landed only in 0.18.2, a
  semver-major move, so the three manifests declaring `lru` moved with it.
  `lru` is declared by `fission-dynamic` and `fission-pcode` but actually used
  only in `fission-static`, at three cache sites.

Five have no fixed version and joined the documented baseline in `deny.toml`
and `.cargo/audit.toml`: the `im` family (`im`, `bitmaps`, `sized-chunks`) and
`smartstring`, all marked unmaintained upstream in 2026-08. `im` is a *direct*
`fission-emulator` dependency, so migrating off it is the real fix; that is a
code change and is tracked separately rather than rushed into a patch release.

`cargo audit` does not read `deny.toml` — `.cargo/audit.toml` says so on its
own first line — so both files were updated. `RUSTSEC-2026-0255` appears only
in `cargo audit`'s output but is listed in both to keep them aligned.

## Verification

- **L0 CI Fast Gate green** on `3ec1b0162`: lint, security, tests on Linux,
  macOS, and Windows, CLI smoke, and the NIR regression gate — the first green
  Fast Gate since 2026-08-11.
- **L1 CI Heavy Validation green** on the same commit.
- **L2 Release E2E** run by `release-tag.yml` as part of cutting this tag,
  which is the documented promotion path (`docs/CI_RELEASE_GATES.md`).
  v0.2.0's tag was pushed by hand, which fired CD directly and skipped L0, L1,
  and L2 entirely; that is what let the incomplete bundle ship.
- `cargo deny check` clean on advisories, bans, licenses, and sources;
  `cargo audit --deny warnings` clean.
- 1,088 tests pass across `fission-static`, `fission-pcode`, and
  `fission-dynamic` on `lru` 0.18.2.

## Decompiler output

Unchanged from v0.2.0. The structuring numbers in
[`v0.2.0.md`](v0.2.0.md) still stand: 621 explicit gotos across DecBench's 224
binaries / 250 functions in both NIR and HIR, and 597 against Ghidra's 691 and
angr's 420 on the 204 functions all three tools decompile.
