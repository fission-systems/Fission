# Fission v0.1.9

Fission 0.1.9 is a **decompiler-engine performance and security** release.
Where 0.1.8's headline work was GUI-facing, 0.1.9 focuses on the decode/
normalize/structuring pipeline itself: a sequence of profiling-driven fixes
to Sleigh instruction decode, HIR normalization, and scalar SSA construction,
plus a security fix for rkyv's checked-deserialization path used by TTD
snapshots. Alongside the performance work, this release also lands the
"switch recovery without a jump table" feature (binary-search and linear
if-chain lowering shapes), an HIR-level semantic variable-naming pass, and a
real escape-analysis pass for stack-slot memory writes.

Tagged commit: `bdb78fb9c`
Release: https://github.com/fission-systems/Fission/releases/tag/v0.1.9

## Release summary

| Area | v0.1.8 | v0.1.9 |
| --- | --- | --- |
| Sleigh decode hot path | `CompiledDisjointPattern`/match-trace/operand-spec/handle-template data deep-cloned on every constructor visit; per-decode-frame `String` allocations | Arc-shared across the whole selection/walk path; per-walk `context_changes`/`decode_steps` clones removed via lifetime-decoupled borrowing; `probe_values` returns a `SmallVec` instead of heap-allocating a `Vec` for the overwhelmingly common single-value case |
| FID/decompile decode | FID signature matching and the main decompile pass each decoded the same function independently | A completed, `TerminalControlFlow`-stopped decode is cached per `FactStore` and reused across the two passes |
| Normalize: dead/unused binding cleanup | `prune_unused_temp_bindings`/`prune_unused_dead_local_bindings` re-walked the whole function body once per local binding (O(locals × body size)), called from ~30 pipeline call sites | Both build a `DefUseMap` once per call and do O(1) lookups per binding |
| Normalize: type inference | `apply_use_driven_type_infer_pass`'s 4-round convergence loop rebuilt use-role classification and `DefinitionDependencyMap` from scratch every round, including redundantly inside `restore_scalar_only_pointer_locals` | Round-invariant facts (use-role classification, the dependency graph) computed once and threaded through instead of rebuilt per round |
| Scalar SSA dominance | Full per-block dominator `BTreeSet` computed via an unbounded fixed-point loop (clone/intersect every reachable block's set on every iteration) | Reverse-postorder + iterative idom-array intersection (Cooper, Harvey & Kennedy 2001); `dominates()` walks the (shallow) idom chain instead of an O(1) but expensive-to-build full-set membership check |
| PreviewBuilder fresh-name generation | Checking whether a candidate name collided with an existing param/local scanned both collections linearly, in a loop that retries on collision | Name set tracked incrementally; O(1) lookup |
| Switch recovery | Only jump-table-based switches recovered | Also recovers switches lowered as a binary-search `Select` decision tree or a linear if-chain, including biased-subtraction unsigned range checks |
| Variable naming (HIR) | Generic `param_N`/`uVarN`/`iVarN` placeholders | Names inferred from usage: pointer dereference/arithmetic, linked-list traversal, well-known libc argument roles, loop induction variables (NIR stays mechanical and oracle-scored; this is HIR-only per ADR 0011) |
| Stack-slot escape analysis | `Call`'s conservative write-effect treated every promoted stack slot as written by every call | Real escape analysis (`compute_escaping_stack_storages`): a slot's address must actually be taken (spilled, returned, or passed in an ABI argument register) before a call is assumed to write through it |
| Dependency security | rkyv 0.7.46 (RUSTSEC-2026-0235: checked shared-pointer validation could be bypassed by an archive with mismatched Rc/Arc pointer metadata at a reused address, enabling out-of-bounds reads through safe indexing) | Migrated to rkyv 0.8.18 across all 6 dependent crates; advisory resolved |

## Sleigh decode and decompile-pipeline performance

Profiling-driven, corpus-verified fixes across the decode/normalize/
structuring stack. Each was measured against the full 209-binary dev+
realworld+holdout corpus for byte-identical output before/after, plus the
full workspace test suite, before landing:

- **Arc-sharing across the Sleigh runtime**: `CompiledDisjointPattern`,
  `RuntimeMatchTrace`, operand specs, constructor/display templates, and
  fixed-varnode names were deep-cloned on the per-instruction decode hot
  path (once per constructor visit, once per backtracking decision-tree
  branch). Wrapped in `Arc` at their compile-time construction sites so
  hot-path clones become refcount bumps. The decision-tree match trace's
  `probes` list also moved from a `Vec` (O(depth) clone per backtracking
  branch) to a persistent structure-sharing linked list (O(1) clone).
- **Constructor-selection cache: investigated, not implemented.** Before
  landing a proposed global constructor-selection result cache, we
  re-profiled after the Arc-sharing work above: `select_constructor`/
  `walk_decision_tree` had dropped to ~0.05% of leaf samples, well under the
  "still a meaningful bottleneck" bar that would justify the cache's
  complexity (per-frontend scoping, exact selection-read-footprint keying,
  sharded bounded cache with shadow verification, cross-architecture
  differential testing). Deferred in favor of the smaller, lower-risk wins
  below, which the reprofile showed were the actual remaining cost.
- **Per-walk clone removal**: `CompiledParserWalker::walk` cloned
  `constructor.context_changes` and `constructor_template.decode_steps`
  wholesale on every constructor walk purely to sidestep a borrow-checker
  conflict with `&mut self` calls inside the loop. Since
  `RuntimeSelection::constructor` is a plain reference whose lifetime is
  independent of the walker's own borrow, copying that reference out once
  decouples the loops from `self` entirely, eliminating the clones with no
  behavior change.
- **`FactStore`-scoped decode cache**: FID signature matching and the main
  decompile pass each independently decoded the same function. A completed,
  `TerminalControlFlow`-stopped decode (the only state safe to reuse across
  different decode budgets/contracts) is now cached per `FactStore` and
  reused between the two passes.
- **Normalize O(locals × body) passes**: `prune_unused_temp_bindings`/
  `prune_unused_dead_local_bindings` re-walked the entire function body once
  per local binding inside a `.retain()`, and are called from roughly 30
  sites across the normalize pipeline. Both now build the existing
  `DefUseMap` once per call instead.
- **Type-inference round-invariant recomputation**: `apply_use_driven_
  type_infer_pass`'s 4-round convergence loop rebuilt use-role
  classification (`collect_binding_use_roles`, which only reads expression
  shape, never a binding's current type) and `DefinitionDependencyMap`
  (whose dependency graph reflects the HIR's shape, not current types) from
  scratch every round -- including redundantly again inside
  `restore_scalar_only_pointer_locals`. Both are now computed once and
  threaded through, cutting up to 8 full-body walks per call down to 1.
- **Scalar SSA dominance algorithm**: `Dominance::analyze` computed a full
  dominator set per block via an unbounded fixed-point loop, cloning/
  intersecting a `BTreeSet` of (up to) every reachable block on every
  iteration, then derived immediate dominators afterward by picking the
  largest set per block. Replaced with the standard reverse-postorder +
  iterative idom-array intersection algorithm (Cooper, Harvey & Kennedy,
  2001) already used elsewhere in the codebase (`fission-midend-structuring`'s
  `ImmDomTree`); `dominates()` now walks the idom chain instead of doing a
  full-set membership check.
- **`PreviewBuilder` fresh-name generation**: checking whether a candidate
  temp/local name collided with an existing binding scanned params and
  locals linearly on every candidate, inside a loop that retries on
  collision. Now tracked in a name set for O(1) lookup.

## Switch recovery without a jump table

Extends switch-statement recovery beyond the jump-table case to two more
lowering shapes found in the corpus:

- **Linear if-chain**: a chain of `if (x == c1) ... else if (x == c2) ...`
  comparisons collapsed back into a single `switch`.
- **Binary-search decision tree**: GCC's binary-search-style lowering, which
  mixes equality splits (case boundaries) with range splits (`x > c`, pure
  search-tree narrowing) into one `Select` tree. Recovery only recurses into
  a `Select` as "still inside the tree" through a direct `x CMP const`
  comparison (or bare `!x`) -- an unrelated variable's condition, or
  arithmetic on `x`, is always treated as an opaque case leaf, so an
  unrelated ternary inside a case body can't be misread as another split.
  Non-case leaves must all be structurally identical before a `default` is
  accepted, since these trees routinely reach the same default through
  several differently-shaped leaves.
- **Biased-subtraction unsigned range checks**: recognizes the
  `(x - low) <= (high - low)` idiom (a signed range check rewritten as a
  single unsigned comparison) as a switch bound, not a generic subtraction.

## HIR-level semantic variable naming

Generic `param_N`/`uVarN`/`iVarN`/`xVarN`/`bVarN` placeholders are replaced
with names inferred from how a variable is used: pointer dereference and
arithmetic, linked-list traversal, well-known libc argument roles, and loop
induction variables -- mirroring angr's semantic-naming design. This is
HIR-only per ADR 0011: NIR remains mechanical and oracle-scored, only the
dashboard's readability-facing layer changes.

## Real stack-slot escape analysis

`MemoryLayout::write_effect`'s `Call` case previously treated every
function call as writing to every promoted stack slot -- correct in
general (a callee can write through an escaped local's address) but
imprecise for the common case of a non-escaping local sitting near an
unrelated call. `compute_escaping_stack_storages` now requires a stack
slot's address to actually be taken -- spilled elsewhere (a `Store`'s
value operand), returned, or passed in one of the calling convention's
integer argument-passing registers -- before a call is assumed to write
through it.

## Security: rkyv 0.7 -> 0.8 (RUSTSEC-2026-0235)

rkyv 0.7's checked-access path (`rkyv::check_archived_root`, used directly
by `fission-dynamic`'s TTD snapshot loader) is RUSTSEC-2026-0235: shared-
pointer validation keyed already-validated pointees by address only, not
pointer metadata, so a crafted archive could contain multiple `Rc`/`Arc`/
weak pointers sharing an address with different metadata (e.g. different
slice lengths); once the first pointer validated, later ones to the same
address skipped pointee validation, letting safe indexing read out of
bounds. The 0.7 series has no fix and is no longer supported upstream.

Migrated all 6 crates depending on rkyv (`fission-core`, `fission-loader`,
`fission-pcode`, `fission-dynamic`, `fission-static`, `fission-sleigh`) to
0.8.18: the `#[archive(...)]` attribute syntax was replaced by `#[rkyv(...)]`
throughout (including explicit `serialize_bounds`/`deserialize_bounds`/
`bytecheck(bounds(...))` on `fission-sleigh`'s two self-recursive pattern/
expression enums), `fission-loader`'s hand-written `Arc<DataBuffer>` <->
`Vec<u8>` wrapper impls were ported to 0.8's non-unsafe `resolve`/
`resolve_with` (`Place<T>` output) and split serializer traits, and
`fission-dynamic`'s snapshot save/load now uses 0.8's `to_bytes`/
`from_bytes` free functions (which validate and deserialize in one call,
using the corrected pointer validation) in place of the old manual
validate-then-deserialize dance.
