# Fission v0.2.3

The sample-set structure score went from 52 to 64 functions recovered exactly.
The more consequential change is a class of defect no benchmark metric was
looking at: the emitted C was, in several specific ways, not doing what the
binary does. Those are fixed here.

## Release summary

| --- | --- | --- |

| Sample-set scorable rows | 232 | 233 |

## The emitted C was losing side effects

SLEIGH lowers an absolute-addressed write (`mov dword ptr [rip+N], 0`) to an
ordinary op whose *output varnode lives in ram space*, not to a `Store`. Such
an output reached the generic materialization path and was judged by rules
that all ask the same question -- does anything read this value back? Nothing
reads a global inside the function that writes it, so the write was dropped.
Measured over the sample set's own requested functions, one of 46 such writes
survived into the emitted C, and the same one in `v0.1.9`. This was not a
regression; it had always been there.

Telling ram from unique needs the *engine*, not the varnode: the two lifters
collide on space 3 -- the legacy engine's unique space is the runtime's ram --
and offsets cannot break the tie either, because a PIE image maps its sections
from a low base, so the runtime's own unique offsets look like mapped
addresses. It is decided once per function from the space ids the whole op
stream uses.

Three passes then had to agree that the name meant memory, and each re-derived
it from spelling or the symbol table; the first attempt at the presentation
layer was silently half-effective for exactly that reason. A direct RAM output
now carries `Deref { ptr: AddressOfGlobal(name) }`, the shape the `Store` path
already used, so the representation proves what each pass previously guessed.

## Arguments a call never received

Three separate defects put values into argument lists that were not arguments.

An x86 `call` lowers to `RSP = RSP - 8; STORE ram[RSP], <next instruction>;
CALL target`, and that store lands at stack offset zero -- exactly where the
first stack argument would be. Sixty-six of the sample set's 250 rows carried
a trailing argument equal to the address of the instruction after the call:
`__stack_chk_fail(16267)` on a function that takes none. The x86-32 recovery
path had skipped these all along; the 64-bit one never did.

Every argument register is caller-saved, so a call anywhere between a
definition and a call site destroys the value. `check_ancestor_realistic`
carried that rule from Ghidra but swept only the blocks strictly *between* the
definition's block and the call's, and a call sits at an end of that path far
more often than in the middle -- a block that ends in one, with the next block
starting at the next call, is what two calls in a row look like. `setutent()`,
which takes no parameters, came out as `setutent(14, __act, 0, xVar25)`: the
preceding `sigaction`'s.

A call clobbers the ABI's result register, so a later read of it that liveness
cannot rule out made the call site materialize a receiver. On a function that
returns nothing that produced `rax = free(ptr);` -- not valid C, and not true.

## A function passed as data is a function

`global_names` resolved a constant to a symbol using the import table, the
global symbols and the string literals, but never the functions. So a function
handed to a callback printed as a bare integer: coreutils `ls` passes `strcmp`
to a comparator and we emitted `sub_ad02(a, b, 46050, b)`; `signal(15, 41168)`
instead of the handler's name.

## Thumb

Two defects, both found by disassembling `nuttx` against `objdump`.

A branch to its own address is a genuine machine-level self-loop -- Thumb's
`b .`, the idiom every Cortex-M `Default_Handler` ends in -- and the CFG
builder was erasing it, because it decided on the resulting address rather
than on how the target resolved. One block where there were two, no back edge,
and a body that rendered as a bare `goto` to the function entry.

Separately, `normalize_low_bit_code_address` can only speak for the address it
is given, so every even-addressed function of a Cortex-M image -- which cannot
execute ARM at all -- was disassembled in the language's default ARM mode.
Misreading Thumb as ARM rarely fails outright: `80 b5`, a `push {r7,lr}`, reads
as `addlt r11,r2,r0`. The decompile path already resolved this per address;
the shared disassembly primitive, which the CLI and the server's `/api/disasm`
both use, had no equivalent.

## Ghidra's no-return lists were matching nothing

`NoReturnFunctionAnalyzer` normalises a name by stripping leading `'_'` chars
in a loop. The port stripped exactly one, and a test pinned that. Not one entry
in the shipped lists starts with an underscore, while the names they exist to
match are `__stack_chk_fail`, `__assert_fail`, `_Unwind_Resume`,
`__longjmp_chk` -- so the single most common no-return call in a glibc binary
was never recognised as one.

## Structure

Beyond the correctness work, the sample-set structure score moved on four
changes, each gated against the recorded floor: a branch that leaves the
function no longer fabricates a block edge inside it; the stack-protector check
is elided, because it is not in the source; a return is duplicated into the
arms that fall into it; and the `else` behind an arm that leaves is unwrapped
only when that arm actually leaves.

Alternative structuring drivers gained experimental controls
(`FISSION_EXPERIMENTAL_STRUCTURING_ORACLE`) and now report why a driver
declined, which is how we established that the candidate space is not the
bottleneck.

## Types

Nine changes to call-contract recovery: exact imported call arguments, gettext
contracts, POSIX signatures, the ELF `main` callback prototype, x64 stack
parameters, and direct-callee pointer evidence that survives a copy. Sample-set
type accuracy is unchanged at 14 of 222; the dev-corpus work is where these
show.

## Performance and CI

Several unbounded walks now carry budgets -- varnode lowering, the idom climb,
a branchy region's reaching condition, the direct-callee prototype preview --
and two hot paths cache what a block already answered. Formatting is checked
across the workspace rather than only on changed files.

## Known defect

A loop-latch arm loses its body. Given a header, an arm whose statement is a
write to a mapped global and whose terminator is an unconditional branch back
to the header, and an exit, the write reaches `lower_block_stmts` and is absent
from the body structuring assembles: `while (!rax) { }`, an empty loop. This
owns the last 16 dropped global writes on the sample set, all in two
option-parsing loops. Recorded as an ignored test,
`backedge_arm_keeps_its_global_write`, which is a specification for the fix
rather than the fix.
