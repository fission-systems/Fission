# Known divergences between the host CPU and Fission's lift + interpreter.
#
# One line per instruction: <isa> <MNEMONIC> <fields|*> #<issue> <reason>
#   isa       x86_64 | aarch64
#   MNEMONIC  as Fission's disassembler prints it, upper case; `*` covers the
#             listed fields for every instruction (a spec-wide gap), and a
#             trailing `*` a family (`LDADD*`: LDADDB, LDADDAH, ...)
#   fields    the comma-separated fields allowed to differ (register names,
#             flags, `mem`, `fault`, `panic`, `decode`), `*`, or a tag:
#             `~nan` (both sides NaN, payloads differ), `~fp16` (the
#             instruction does half-precision float arithmetic)
#   issue     the GitHub issue tracking the fix
#
# The gate fails on a divergence not covered here and on an entry that no
# longer reproduces. A divergence found only by a long random run must get a
# curated case before it is listed, so that the pull-request run reproduces it.
# Where even the curated case hits it too rarely for the pull-request count
# (a one-ulp fused-rounding difference), the reason says `@nightly`: smaller
# runs then do not call the entry stale; the nightly run still does.
# Where host CPUs themselves disagree (one runner reproduces it and another
# does not, on the same tree), the reason says `@host`: no run calls it stale.

# ── x86-64 ──────────────────────────────────────────────────────────────────
# Evaluator: which NaN propagates is left to the host's float ops; x86
# propagates the first source (`~nan`: both sides NaN, payloads differ).
# Since #1049/#1050 the PR-size run hits it only in DPPS on Intel hosts; an
# AMD EPYC host agrees with Fission there, so it is `@host`.
x86_64 * ~nan #1055 NaN payload / operand order @host
# Host: f3 41 90 is xchg r8d, eax (90+rd with REX.B, SDM) and Fission decodes it so;
# a host CPU that runs it as PAUSE leaves RAX and R8 alone.
x86_64 XCHG RAX,R8 #1059 f3 41 90 executed as PAUSE on some hosts @host

# ── AArch64 ─────────────────────────────────────────────────────────────────
# Spec: fused multiply-adds round twice (p-code has no fused operation, so the
# lift is a product and a sum; FPNeg is applied to the operands).
aarch64 FMSUB * #1072 not fused @nightly
aarch64 FMLA * #1072 not fused @nightly
aarch64 FMLS * #1072 not fused @nightly
# Runtime: attach-variables tables drop their `_` holes, so CASP's pair
# registers are mis-indexed (`casp w2, w3, ...` reads w5 and w4, w9).
aarch64 CASP* * #1391 pair registers mis-indexed by a dropped varlist hole
# Spec: FPProcessNaNs3 gives a signalling NaN in any operand priority; the
# product-then-sum lift can propagate another one.
aarch64 FMLAL* ~nan #1397 signalling NaN priority not modelled @nightly
