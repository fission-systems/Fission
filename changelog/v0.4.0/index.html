    Fission v0.4.0¶

    Most of the 116 pull requests merged since v0.3.0 are correctness fixes. In many of them the printed C did something other than what the binary does: - a call printed twice - an argument the machine does not pass - a global read at the wrong time - a switch case attached to the wrong value - code printed after a jump that never comes back

    None of these changes the shape of the control flow, so the structure score could not see most of them. They were found by the new verify command, which checks the printed code against the machine, and by reading changed output against the disassembly.

    Decompiling is also faster: three performance passes cut full-dataset time by 42%, 38% and 11.5% (CPU). And the CLI exposes more of what Fission already computes: raw images, sandbox exploration, calling a function, stepping back in a debug session, type and API lookups. Every --json output now has a shape that tests pin.

    Installing¶

    # Homebrew (macOS, Linux)
brew install fission-systems/tap/fission-cli

# Install script (macOS, Linux): installs into ~/.local and checks the SHA-256
curl -fsSL https://raw.githubusercontent.com/fission-systems/Fission/main/install.sh | sh

    Cargo builds from source. The processor specifications and signatures come from this release:

    cargo install --locked --git https://github.com/fission-systems/Fission --tag v0.4.0 fission-cli
mkdir -p ~/.cargo/share/fission
curl -fsSL https://github.com/fission-systems/Fission/releases/download/v0.4.0/fission-resources.tar.gz \
  | tar -xz -C ~/.cargo/share/fission

    Archives are attached to the release for five targets:

    Platform Archive
    Linux x86-64 fission-x86_64-unknown-linux-gnu.tar.gz
    Linux arm64 fission-aarch64-unknown-linux-gnu.tar.gz
    macOS Apple silicon fission-aarch64-apple-darwin.tar.gz
    macOS Intel fission-x86_64-apple-darwin.tar.gz
    Windows x64 fission-x86_64-pc-windows-msvc.zip

    Unpack one anywhere and run bin/fission_cli; it finds share/fission/ next to itself. SHA256SUMS covers every asset.

    The printed C was wrong in these places¶

    • Calls printed twice, or with arguments the machine does not pass.
    • call write; leave; ret printed as write(fd, buf, n); return write();. A call's result is now the value the following ret returns (#929).
    • A call's arguments are the registers it reads where it is made. A prologue push rbp is no longer read as a stack argument: fcntl(fd) becomes fcntl(fd, 3, 0) (#932).
    • A float or double parameter no longer takes an integer argument slot on SysV and AArch64 (#1013).
    • Arguments that differ per path into a call are kept. dcgettext calls printed with all three arguments rose from 2,861 to 3,589 on the full dataset, and one-argument calls fell from 168 to 0 (#1019).
    • Switch case values were attached to the wrong targets. In tar, 'R' printed under case 74 instead of 82. A jump table's default is now the range check's out-of-range target, so unused entries stop printing as dozens of case N: arms (#1019).
    • Globals:
    • A global is read where the machine reads it, and a read after a call is a fresh load (#930, #931).
    • Part of a named global is accessed through its address (#933).
    • A test of a register copied from a global tests the global (#934).
    • Code after a jump that leaves the function was printed as if it ran. On a 453-row sample, statements after a tail jump went from 322 sites in 186 functions to 14 in 13 (#1039).
    • Flags and casts:
    • A flag is a snapshot, so a Thumb subs; it ne; movne boolean no longer prints as a branch on a named flag (#900).
    • Unsigned casts are restored in every statement and loop condition. (uint)(uchar)x keeps its truncation (#901).
    • Conditions folded on the wrong path. A remembered path condition now ends at a memory write, a label or a call. At -O0, r = f(); if (r) return r; r = g(); if (r) return r; lost its second test (#919).
    • Inlining past a write. A definition is no longer inlined past a store to its input (#952).
    • Stack-protector checks are removed in four layouts instead of one (#903).
    • Output explosion. One guarded-tail rewrite deleted jumps over live code and copied the rest of a ladder into both arms; process_row printed 1.24 MB for a 40-line function (#1023).
    • Output depended on the host CPU. The same binary decompiled to 4.4 KB on aarch64 and 17.8 MB on x86-64, because a hash set's iteration order chose a follow block (#1025). Where several symbols share a name, the choice is now by address order too (#986).
    • char and short parameters are declared at the width the compiler stores them in their stack home. The type-perfect count rose by 274 on the full dataset (#1066). See Known issues.
    • SLEIGH runtime and optimizer:
    • Fixes to pattern offsets, non-RAM branch targets, relative-label sign extension and decode context (#993).
    • Constructor nesting is bounded at Ghidra's parse depth (#1009).
    • Optimizer soundness and sub-register aliasing in fission-pcode-ir (#1015).
    • C23. Inferred callee declarations compile under C17 and C23 (#1016).

    Checking output against the machine¶

    fission_cli verify --tier ground-truth runs the printed tree and the machine code on the same inputs, with memory, globals and stubbed calls. It compares the return value, every call with its arguments, and every store outside the frame, and it can check a whole binary (#927, #951, #954, #955, #961). On gzip -O0, functions proved equivalent went from 11 to 82. A diverged function is a lead to read against the disassembly, not a verdict.

    A native replay fixture compares the real CPU, the emulator and the printed code on identical inputs. A small integer subset of the printed code can be exported to Python (#1020).

    Two decisions are recorded as ADRs: - ADR 0017: Ghidra is a reference, not a correctness oracle. Its SLEIGH specifications were wrong for AArch64 FCVT and FRINT, and Fission patches them locally. - ADR 0018: DecBench measures similarity to the source, not correctness.

    For agents¶

    • New commands:
    • call runs one function in the emulator with arguments you choose (#1006).
    • types, whatis and api look up recovered types, addresses and known API signatures (#1008).
    • languages lists the available processors (#991).
    • Raw images: firmware, shellcode and memory dumps load with --base/--entry (#991).
    • Debug sessions can step back (#1006), and every session command attaches (#957).
    • sandbox reports exploration, time-travel state and snapshots as data (#996).
    • decomp carries globals, layout, DWARF source lines and verify results in its JSON (#988, #991).
    • Flags:
    • Flags that used to do nothing silently now say so (#988).
    • --work-limit sets the decompiler's work limits and reports when one cut work. The defaults are unchanged (#1038).
    • Stable shapes:
    • The shape of every --json output is pinned by tests, so a removed or renamed key fails CI (#1011).
    • fission_cli schema <command> prints JSON Schemas for info, list and decomp (#1020).
    • --contract v1 error and schema routing is fixed (#989).

    Faster¶

    Change Measured on the full DecBench dataset
    Loop hoisting, global index, partial-register scan, SSA validation (#883) −42%
    Callee previews, type fixed point, guard crossings, per-query scans (#899) −38%
    Three repeated per-function scans (#977) −11.5% CPU

    Also: - No-return preparation runs in parallel (#1041). - Masked Ghidra function-start patterns are indexed (#1034). - Discovery reuses its decodes (#1040, #1044). - Control-flow facts are built without a full xref index (#1042). - Worker stacks and type context are reused (#982). - Mach-O function boundaries are binary-searched, and the DiE matcher is prepared once per process (#1021, #1022). - SLEIGH decoding classifies control flow once and keeps less state per operand (#1026–#1029). - Covered pattern hits and indexed call targets skip revalidation (#1024, #1030).

    The PRs report speedups under their own loads. Measured together for this release, decompiling the full dataset takes 53% less CPU time than v0.3.0 (11,890 s → 5,608 s; see Quality numbers).

    Emulation and debugging¶

    • Emulator:
    • Fixed a JIT temporary-cache miscompile (#941).
    • Fixed JIT and interpreter disagreements from three audits: a failed cmpxchg that still stored, snapshots that lost registers, mmap overflow, TTD forward seek, and soft-float conversion (#948, #949, #950, #958).
    • Guest ABIs:
    • Windows guests get cooperative threads, events, waits and per-thread TLS, which a cgo Go program needs before main (#942).
    • Linux and Windows guests are answered in their own ABI: stat, iovec, auxv, dynamic linking, int 0x80, string conversion, CRT realloc, 32-bit structure sizes (#965, #975).
    • Debugger:
    • On macOS and Linux, a trap is classified by the thread that took it (#966).
    • GDB/MI lists terminate and keep their entries (#956).
    • The Windows native debugger rewinds and steps off breakpoints, and reads PE and OS structures by checked offsets (#973). See Known issues.

    Robustness¶

    • Hostile inputs:
    • Hostile headers are refused instead of panicking (#960).
    • Mach-O load commands are bounded (#962).
    • Loader fixes for raw word size, LSDA byte order, DWARF 5 names, cyclic PDB types and COFF string tables (#967, #968).
    • Solver:
    • Fixed assumption backtracking, AIG bits, the array axioms, and constants read at another width (#936, #963, #970).
    • The z3 differential now covers 64-bit vectors, arrays and incremental queries (#964).
    • SAT restarts follow the Luby sequence (#974).
    • Other crates: bounds and lifetime fixes in signatures, core, static, cspec, project, script and plugin (#937, #938, #940, #944, #946, #947).

    CI¶

    Every merge to main now goes through a merge queue. Required checks depend only on the change, and a red nightly opens an issue (#980, #984, #985). - Nightly: the full DecBench dataset (96,103 functions) is swept every night (#980). - Lint: actions are pinned, and clippy runs with --all-targets (#985, #1017). - Fuzzing covers more targets (#997). - Tests: a test whose input is missing now fails instead of passing silently (#1012).

    Quality numbers¶

    Full DecBench dataset (770 binaries), local sweep, caches disabled, both released aarch64-apple-darwin binaries:

    full (91.6k GED-scored rows) v0.3.0 v0.4.0
    GED exact matches 31,982 32,560 (+578)
    GED total distance 1,605,260 1,544,605 (−3.8%)
    Type exact matches (of 86,937) 5,697 6,167 (+470)
    Type mean 0.2258 0.2355
    Union (GED or type exact) 35,325 36,034 (+709)
    Decompile CPU time 11,890 s 5,608 s (−53%)
    Decompile failures 0 0

    By config, GED exact matches and total distance went from v0.3.0 to v0.4.0 as follows: - unoptimized: 13,260 → 13,465, distance 399,120 → 381,371 - optimized: 11,184 → 11,418, distance 562,165 → 532,914 - inlined: 7,538 → 7,677, distance 643,975 → 630,320

    GED (structure) measures how close the output's control flow is to the source's. It does not measure correctness (ADR 0018).

    Known issues¶

    • Signedness bug (#1066). A parameter whose stack home is read both sign-extended and unsigned can be declared char, which turns a % signed. One case is known (an AArch64 USB driver function). Fixed on main by #1098, for v0.4.1.
    • One jump table lost. In tar's O2 no-inline build, the function at 0x11730 recovers one of its two switch tables. The PR that caused it has not been found.
    • Windows native debug sessions.
    • debug session <exe> reads registers with the process id as the thread id, so regs fails with "OpenThread failed".
    • event can fail while a debug event is pending.
    • The fix is #1045, which still needs a run on Windows.
    • modules reports the main image as <unknown>.
    • Lift errors found by native execution. Running single instructions on real x86-64 and AArch64 CPUs against Fission's p-code found 22 divergences (#1048–#1072):
    • x86 AF, CVT rounding, XADD and XCHG forms
    • AArch64 FCVT saturation, FRINT ties, LSE atomics
    • evaluator NaN propagation and half-precision floats

    The CI job that runs this differential (#1073) is not yet merged. - Contract. Per-command data schemas exist for info, list and decomp only.
