    Fission v0.1.8¶

    Fission 0.1.8 is a GUI-maturity and cloud-correctness release. Where 0.1.7's headline work was architectural (the browser frontend, fission-ui extraction, fission-serve, DIR independence), 0.1.8 focuses on closing the gap between the GUI and a real RE tool and on hardening fission-serve itself: a raw Disassembly view with inline per-address comments and sidecar-file persistence, a whole-binary Call Graph browser, several real Dioxus hook-ordering bugs that made whole panels (Disassembly, Hex, CFG) show stale or empty content after switching functions, and a run of fission-serve performance and correctness fixes (session-scoped FactStore/XrefIndex caching, rayon thread-pool sizing on constrained containers, background-discovery tuning) found by exercising the cloud deployment against large real binaries.

    This remains a pre-1.0 minor release: the documented CLI is the primary interface. NIR remains the semantic oracle; HIR is a clone-only readability polish layer, and DIR stays independent of both.

    Tagged commit: 57a0a9d0 Release: https://github.com/fission-systems/Fission/releases/tag/v0.1.8

    GUI: Disassembly view, comments, and project persistence¶

    The most conspicuous gap versus a real RE tool was no raw disassembly view and no per-address comments; renames also didn't survive a reload. Closed in three phases:

    • Phase A — Disassembly view: extracted disassemble_function out of fission-cli's CLI-only oneshot::disasm module into a shared fission-decompiler primitive (address, hex bytes, decoded text, direct call/jump target), exposed over GET /api/disasm/:session/:addr, and wired into fission-ui as a new "Disasm" tab with click-to-navigate on rows carrying a direct target. Verified byte-identical fission_cli disasm output before/after the extraction.
    • Phase B — Comments: per-address comments (AppState.comments), editable inline on each disasm row (double-click to edit, Enter commits, Escape cancels, empty clears) — mirrors the existing function-rename inline-edit UX.
    • Phase C — Sidecar persistence: extends the existing (previously read-only) <binary>.fission.json sidecar with a user_comments key. "Save Project" (File menu / Cmd+S, native only) read-modify-writes user_function_names/user_comments without disturbing hand-edited user_structs; loading a binary now pre-populates the GUI's own rename_map/comments from any existing sidecar instead of only feeding FactStore's name resolution one-way.

    GUI: Call Graph sidebar tab¶

    A new whole-binary caller/callee browser (GET /api/callgraph/:session), sortable by caller count, callee count, or name, with search and click-to- navigate — the highest value-per-effort item identified in a CLI/GUI feature-gap survey, since the underlying data (XrefIndex/CallGraph) was already there. CallGraph::build_from_xref_index aggregates Call-kind xrefs directly from the already-cached XrefIndex instead of re-running a second whole-binary disassembly pass; verified against fission_cli callgraph --json on the same binary (total_call_sites and top caller counts match exactly) and live in the Railway-deployed backend.

    GUI correctness: three Dioxus hook-ordering bugs¶

    All three surfaced as "a panel shows the previous function's content, or nothing, after switching functions" — the common root cause was a use_effect/use_signal call living inside a conditional branch (a match arm, an if, or after an early return) instead of unconditionally at the top of the component. Dioxus requires every hook to be called in the same order on every render; skipping a hook's call site on some renders desyncs its hook-slot bookkeeping from the rest of the component.

    • editor.rs: the Disasm-tab fetch effect, the Hex-tab scroll-into-view effect, and the find-bar scroll-into-view effect were each nested inside their respective tab/visibility branch. Hoisted to the top of Editor(), unconditional, with the branching moved inside each effect's body.
    • cfg_view.rs: five use_signal calls for pan/zoom state (scale/offset_x/offset_y/panning/pan_xy) were declared after an early return for the "no CFG loaded" case. Moved before the return.
    • Also fixed while auditing this: xrefs were loader-only (build_xref_index(binary, false)) on both the server and native paths, producing near-empty results next to fission_cli xrefs's disassembly-based default; switched both to disassembly-based, backed by new session/binary-scoped caches (SessionData::xref_index, engine::xref_index_for) so the cost doesn't recur per click.

    fission-serve performance and correctness¶

    Found by exercising real, large binaries (multi-thousand-function real-world PE files) against the Railway deployment rather than synthetic fixtures:

    • Whole-program call-arity pre-analysis now skipped in cloud mode (kept for local/native use) — it was adding meaningful latency to every cloud upload for a quality benefit that matters more for local batch-decompile workflows.
    • FactStore and the new XrefIndex are cached per session behind a tokio::sync::Mutex held across the entire check-then-build-then-store sequence (not just the check), both to avoid blocking a tokio worker thread and to avoid a thundering herd where concurrent requests on a cold cache each redo the same expensive work.
    • control_flow_facts_for's cache switched from Mutex<LruCache<String, ControlFlowFacts>> to Mutex<LruCache<String, Arc<OnceLock<...>>>>, closing a race where two callers could both see a cache miss and both pay the full computation.
    • Rayon's global thread pool is now explicitly capped (FISSION_RAYON_THREADS, default min(available_parallelism, 8)) instead of trusting available_parallelism(), which reads the host machine's core count on many container runtimes rather than the container's actual cgroup CPU quota — this alone turned a real Railway hang (a ~27k-function binary that parses in under a second locally never returning) into normal latency. Worker stack size widened to 16 MiB, fixing a real production crash (stack '<unknown>' has overflowed its stack, aborting) hit by a legitimate-but-deep recursion in the parse/discovery pipeline.
    • max_sessions default lowered 50 → 10 to bound worst-case memory on a small Railway instance.
    • Binary upload no longer blocks on CFG-based function discovery; discovery moved to a background task with an analyzing flag surfaced through /api/functions so the GUI can show real progress instead of a frozen upload.

    Other GUI fixes¶

    • Sidebar function list batch-rendered instead of rendered in full, fixing real lag at 15k+ functions; a hand-rolled virtual-scroll implementation that had three separate bugs (double-counted wheel deltas, unbounded growth under CSS containment, scroll driven from manual deltas instead of real onscroll) was removed in favor of the simpler batch-render fix.
    • Consolidated five duplicated "jump to function" call sites (xrefs view, command palette, Back/Forward in both main.rs and title_bar.rs) into one navigate_to_address helper.
    • Per-binary state reset centralized into AppState::reset_for_new_binary() after finding it was incomplete or duplicated across all 4 binary-load call sites — most seriously, nav_history/nav_cursor weren't cleared on at least one path, which could navigate to the wrong address after loading a new binary.
    • Fixed: WASM clipboard copy, command palette breaking nav_history, string-click-to-hex-offset scrolling, Find bar next/prev navigation, a dead "Run FID Signatures" menu stub (removed), Export/Save pseudocode to file (native), xrefs row hover using the wrong CSS class selector, and a real panic risk in the Strings tab from byte-index string slicing on non-ASCII decoded binary strings (switched to .chars().take(n)).
    • Web upload/decompile/disasm failures now surface the server's actual {"error": "..."} message instead of a bare HTTP status; the backend-connect token input is now wrapped in a <form> (was a bare <div>, tripping a Chrome DOM warning about password fields outside a form).

    Static analysis / decompiler features¶

    • Transitive no-return function propagation (Ghidra FindNoReturnFunctions Analyzer parity) wired into ControlFlowFacts::assemble.
    • Data-driven callfixup target names parsed from .cspec (Ghidra CallFixupAnalyzer parity), including alloca_probe lookup in entry analysis.
    • Interprocedural callee-arity learning across session decompiles (record_interprocedural_arity_facts), plus an optional whole-program pre-analysis pass that seeds the same facts up front for local/native use.

    Deployment¶

    • Backend deploy split out of the tag-triggered cd.yml into its own push-triggered deploy-backend.yml (matching fission-web's existing push-based model) — waiting for a full gated release tag before a backend fix reached production was too slow a loop for live iteration. cd.yml stays tag-scoped, publishing versioned CLI release assets only.

    Release-gate fixes¶

    Found and fixed while cutting this release itself:

    • A new RustSec advisory (RUSTSEC-2026-0221, published 2026-07-13 against event-listener, transitive via rfd's Linux file-dialog stack) started failing cargo audit --deny warnings on every main push once the advisory database picked it up, blocking L0 CI Fast Gate. Fixed with a semver-compatible cargo update -p event-listener (5.4.1 → 5.4.2); no direct Cargo.toml pin existed to bump since the dependency is fully transitive.

    Known issues¶

    • selfjit (introduced in v0.1.7) is still not the emulator's default backend and cranelift-* remains in the dependency tree.
    • WASM/web has no local filesystem access, so project-sidecar persistence (renames + comments) stays native-only this release, same as v0.1.7's clipboard/save-to-file gap.
    • direct_target extraction for the new Disassembly view is not yet populated for ARM64 PC-relative branches (a pre-existing fission-sleigh decoder gap) — those rows render without click-to-navigate.
