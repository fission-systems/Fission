    Fission v0.2.2¶

    Two things in v0.2.1 did not work the way its release notes implied, and both are fixed here. One of them was invisible: FID function identification was off in every artifact we shipped.

    If you are installing Fission, use this release rather than v0.2.1.

    Release summary¶

    Area v0.2.1 v0.2.2
    FID function identification resolved .fidbf paths that ship nowhere — matching never ran resolves the packed form; matching runs
    32-bit PE symbol names _mul_ints as emitted by the linker mul_ints, the source name
    Type accuracy (24-binary dev corpus, vs DWARF) 0.1237 0.1817 (+5.8pp)
    utils/ downloaded from an assets-v* release pin committed, 1,259 files
    CI on a push to main ~105 min ~30 min

    FID matching was off everywhere it ran¶

    v0.2.0 packed the FID databases into .fpk and moved the source .fidbf to utils/source/, which is gitignored. Path resolution was not updated with them: find_fid_file tested path.exists() on the .fidbf name, so get_preferred_fid_paths and get_library_fid_paths returned empty lists and the match loop never executed.

    That is every tree except an authoring machine — CI, the container image, and any clone. It passed locally for exactly the reason it was hard to notice: a developer checkout still has utils/source/.

    Resolution now counts a database present when its <stem>.fn.fpk is there, the same rule signature tables already used. Reproduced by parking utils/source/ to match a checkout: before, the FID tests failed as CI reported; after, 2,049 tests across the release-critical crates pass with it absent.

    A test was complicit. parses_all_fidbf_for_arch_without_hard_failure accepted !databases.is_empty() || !errors.is_empty(), so it passed while every database failed to load. It now requires loading to succeed.

    i386 PE symbols are undecorated¶

    32-bit x86 Windows decorates C symbols by calling convention — _name for cdecl, _name@N for stdcall, @name@N for fastcall. DWARF, and every source-level view, records the undecorated name. Fission used the COFF symbol verbatim, so on gcc-m32 binaries all 79 functions came out as _mul_ints, ___mingw_invalidParameterHandler, and so on.

    Every gcc-m32 binary in the corpus scored exactly 0.000 on type accuracy — not because the decompilation was wrong, but because no function name could be matched to ground truth. Across 24 dev-corpus binaries: 0.1237 -> 0.1817 (+47% relative), true positives 335 -> 492, and no binary regressed.

    Exactly one underscore comes off, including from names that still begin with one afterwards: __mingw_invalidParameterHandler is the source name and the object file carries ___mingw_.... Mangled symbols (_Z, _R, _$s, ?) are left for the demangler — stripping first turns a readable C++ name into ZN4core3fmtE.

    utils/ is in the repository¶

    v0.2.1 fixed a symptom of the assets-v* bundle mechanism. v0.2.2 removes the mechanism.

    utils/ is now committed — 1,259 files. setup-utils downloads nothing and verifies the checkout instead; the Dockerfile copies from the build context rather than fetching a SHA-pinned tarball (it had been pinned to v0.1.6, so production served resources several releases behind its own code); and no standalone fission-utils.tar.gz is published, because there is no longer anything for it to diverge from. That divergence is what broke v0.2.0: assets-v3 held 1,048 of 3,468 files while reporting 3,468.

    Packing is what made the tree small enough to carry:
    Merged struct corpus (6 JSON -> 2 .fpk) 25.4 MB -> 1.5 MB
    DIE signatures (2,066 .sg -> 1 .fpk) 2,066 files -> 1
    Go patch-version diffs, unread by any code untracked
    YARA rules and two constant tables, likewise untracked
    Tracked total 158 MB -> 103 MB, 3,543 files -> 1,259

    Inputs live under utils/source/, which stays gitignored. Regenerating a .fpk needs them; running Fission does not.

    Also in this release¶

    • Ordinal fallback. PE imports by ordinal now consult Ghidra's export tables where the primary table has no answer.
    • Operand metatypes. The inputTypeLocal half of Ghidra's TypeOp table is seeded at lowering, where map_binary_op would otherwise collapse IntDiv | IntSDiv | FloatDiv into one node. Measured effect on type accuracy is small (+3 of 2,708 ground-truth variables) because 97.8% of the refinements land on temporaries; recorded rather than oversold.
    • .sla context fields. Names and bit ranges are read from the symbol table's header pass, which nothing had read before — 1,021 context symbols across 133 languages, none of which carry a name on the element the parser was looking at.
    • CI. A push run went from ~105 min to ~30: the holdout cohort no longer runs on push (nothing reads it there), seven decompiler images are baked once instead of rebuilt from source every run, and semantic verification and decompilation are cached.

    Verification¶

    • 2,049 tests across the release-critical crates, with utils/source/ absent.
    • Struct corpus verified field-for-field, 22,674 of 22,674, against the JSON merge it replaces; decompiler output byte-identical.
    • DIE corpus compared signature-for-signature against the .sg walk.
    • Type accuracy measured on 24 dev-corpus binaries against DWARF ground truth, before and after, with both binaries built from the same tree.
