    Fission v0.1.7¶

    Fission 0.1.7 is a new-frontends and JIT-independence release. Where 0.1.6 closed a debug-info and Ghidra-parity audit, 0.1.7's headline work is architectural: a self-implemented AArch64/x86-64 JIT (selfjit) that is now differentially verified against Cranelift across a real 16-binary corpus and covers the large majority of opcodes real functions use, a browser-native frontend (fission-web) sharing all UI logic with the desktop app through a newly-extracted fission-ui crate and a new multi-user HTTP API server (fission-serve), and a genuine architectural split between DIR and HIR that makes DIR an independent IR rather than a HIR-shaped clone. Alongside these, a run of real structuring and SSA/heritage correctness fixes were found and fixed via continued Ghidra-parity auditing, and the desktop GUI gained a full round of feature and performance work (command palette, virtual scroll, CFG/Xrefs viewers, batch decompile, FactStore caching).

    This remains a pre-1.0 minor release: the documented CLI is the primary interface. NIR remains the semantic oracle; HIR is a clone-only readability polish layer, and DIR is now explicitly independent of both.

    Tagged commit: 41019f92 Release: https://github.com/fission-systems/Fission/releases/tag/v0.1.7

    Self-implemented JIT (selfjit) — toward removing the Cranelift dependency¶

    selfjit is a from-scratch AArch64-host JIT compiler for p-code translation blocks, built as a drop-in alternative TbBackend next to the existing Cranelift-backed JitCompiler. This release is the bulk of the work toward the documented end goal of retiring cranelift-* from the dependency tree entirely (not yet done — Emulator's default backend is still Cranelift).

    • Implemented Load/Store (narrow and >8-byte wide paths), all 18 Float* opcodes, Call/CallInd/BranchInd/Return/MultiEqual/ Indirect, Extract/Insert, PtrAdd/PtrSub/Piece/SubPiece/ LzCount, IntCarry/IntSCarry/IntSBorrow/PopCount, SegmentOp, and intra-instruction relative Branch/CBranch loops (TZCNT-style p-code loops that previously made selfjit refuse to compile the containing TB).
    • Implemented and verified an x86-64 host backend, exercised on Apple Silicon via Rosetta since no native x86-64 dev machine was available.
    • Built a differential-testing harness that captures real GuestInsn sequences from real corpus binaries, compiles and runs each translation block through both JitCompiler and SelfJitCompiler independently, and diffs the resulting register-space bytes. Widened from a handful of synthetic cases to a 16-binary corpus sweep, then to deep coverage walking from each binary's actual main() entry point rather than only shared CRT startup code.
    • Two real Cranelift-parity bugs found and fixed purely because the differential harness exercised real code the synthetic unit tests never reached: signed narrow-operand sign-extension, and shift-amount clamping to a value's declared width. A third, pre-existing bug in the Cranelift JIT itself was also found and fixed (ensure_var!'s Variable cache was keyed by (space, offset) only, not size, silently aliasing distinct widths at the same offset).
    • Fixed a related emulator bug found along the way: intra-instruction relative branch deltas were miscomputed against the wrong instruction boundary.

    Browser frontend, shared UI crate, and cloud API server¶

    • fission-ui: the desktop GUI's state, engine, and component logic (sidebar, editor, CFG view, command palette, xrefs view, bottom panel) extracted into a shared crate. fission-dioxus (desktop) and the new fission-web (browser) both consume it; only platform-specific glue (title bar, file I/O, dropzone) lives in each frontend crate itself.
    • fission-serve: a new multi-user, session-based decompilation HTTP API server (/api/status, /api/binary, /api/functions/:session, /api/decompile/:session/:addr, /api/xrefs/:session/:addr, /api/session/:session), reachable via fission_cli serve or the standalone binary. Sessions are TTL-swept and bounded by a configurable max-session count and upload size.
    • fission-analysis-protocol: a portable BackendCapabilities/ StatusResponse contract describing what a connected backend can do (native process, local HTTP, cloud HTTP, or in-browser worker; resource access mode; whether it accepts binary uploads or executes on the client), so fission-ui can render an accurate connection status regardless of which backend it's actually talking to.
    • Railway cloud deployment: fission-serve + fission-web are deployable to Railway as a private-backend/public-gateway pair. The original design required a mandatory bearer token in cloud mode; this was changed mid-release to make the token optional, with nginx per-client-IP rate limiting at the fission-web gateway as the default abuse guard instead (see docs/RAILWAY.md). Getting rate limiting actually working required two failed attempts (keying on the raw TCP peer address, then on ngx_http_realip_module's CIDR trust chain) before landing on directly extracting the first X-Forwarded-For entry — Railway's edge proxies through multiple undocumented, rotating internal hops that defeated both earlier approaches.
    • Deployment itself moves from "every push to main auto-deploys" to tag-triggered: a new cd.yml job deploys the exact tagged commit to Railway after the existing release gates pass, and fission-web pins its fission-ui git dependency to the matching Fission release tag instead of floating on main HEAD.

    DIR: an independently-validated decompiler product, not a HIR clone¶

    The pre-structuring decompiler IR was, in practice, shaped like a clone of HIR, and the original DIR/HIR verifier just diffed two snapshots from the same static pipeline — a check blind to any bug the two snapshots shared. This release replaces that with a genuinely independent, p-code-rooted product, landing in stages culminating in an explicit architecture proposal (docs/proposals/2026-07-26-dir-product-foundation-refactor.md, docs/adr/0014-dir-product-vs-prestructure-substrate.md):

    • The static pre-structuring substrate's Dir* types were mechanically renamed to PreHir* and now live in fission-midend-prehir (split out of fission-midend-core) — explicitly documented as internal pipeline substrate that carries no assurance and is never the semantic oracle.
    • fission-verify (the crate that built the emulator-grounded and solver-backed differential checking this release started with) was renamed and refactored into the new fission-dir product crate. It now owns an independent p-code-rooted reconstruction with an explicit assurance report: a first PcodeNative candidate slice (contiguous, side-effect-free single-block integer regions, with a typed expression rather than parsed pseudocode as its executable meaning) is validated by replaying the original operations through fission-emulator for concrete observations and proved or refuted universally by fission-solver, with solver counterexamples replayed back through the emulator before being surfaced. Memory, calls, control flow, wide values, and overlapping storage are rejected outright rather than approximated. The earlier three-tier PreHIR/HIR differential comparison (concrete eval/diff, emulator ground-truth, solver-backed symbolic) is kept as transitional backend infrastructure inside this crate, not as the product's oracle.
    • A fission_cli decomp --dir flag (plus a Python-side consistency check) exposes this validated product from the CLI. One real HIR content-loss bug was found and fixed while building the earlier differential-tier infrastructure this replaced.

    Structuring and SSA/heritage correctness¶

    Found via continued Ghidra-parity auditing against real fixtures (each verified before landing, several with a focused docs/audits/ remeasure note):

    • Orphan loop-continue/break edges rewritten correctly instead of leaving dangling gotos (1ea1a26f, 867f4380, ee492fb6).
    • Wide-stride struct field recovery and PtrOffset rescaling (cb94c87a), live return-value recovery alongside write-only stack locals (446dc4b9).
    • XMM float-lane retyping off full-vector Aggregate bindings (a6624943); Index out-param stores kept and float matrix types recovered (3ca1a786).
    • Multi-emitted labels stripped after total-infinite-loop regions (516a33bc); CollapseStructure selectGoto + graph-only residual emission (b8442d08); TraceDAG likely-goto detection + heritage float type witness (347a4343); exclusive block emission for structured regions (a07a64c1).
    • Named fields now render on recovered fission_agg typedefs (912b4347).
    • New midend passes: heritage SSA + ownership facts (144f9049), overlapping scalar storage refinement (d81cf147), dynamic-effects guarding + high-variable recovery (5227f74a), typed memory heritage promotion (74450b7c).

    Desktop GUI (fission-dioxus)¶

    • Migrated to Dioxus 0.7.
    • New: command palette, virtual scroll, drag-resize panels, CFG viewer, Xrefs viewer, batch decompile, nav history (Back/Forward), View menu handlers, Ctrl+F find bar, strings browser, function hex view, inline rename, kind-filter chips, copy-pseudocode, log timestamps.
    • Fixed: import thunks (IAT stubs) no longer produce self-recursive pseudocode; CSS inlined into the custom head so desktop dev builds reliably load styling.
    • Performance: FactStore is now cached in AppState and eagerly preloaded/prebuilt once per binary load instead of being rebuilt on every single decompile or batch-decompile iteration.

    Other fixes¶

    • SLEIGH oversized pattern shifts are now masked instead of producing undefined shift behavior; non-x86 targets' return-register space resolution fixed (d168056f).
    • The float/double return register is now recognized from .cspec (81c5c364), closing a gap where x64 float-returning functions lost their return value.
    • Removed the dead native_decomp/Ghidra-FFI architecture entirely (7e207d14) after an audit confirmed nothing depended on it.
    • Project migrated from the sjkim1127 to the fission-systems GitHub organization (36918a6c); all cross-repo references (including fission-web's fission-ui git dependency and Railway deploy configs) now point at fission-systems/Fission.

    Release-gate fixes¶

    Found and fixed while cutting this release itself (CI Heavy failed on the version-bump commit; all four were real, pre-existing issues on main unrelated to the work above, not caused by the version bump):

    • Reverted an over-broad "keep write-only stack locals declared" rule (446dc4b9) that let a genuinely-dead stack-resident shadow of a heritage-promoted variable linger long enough to break loop-condition folding elsewhere; the undeclared-identifier bug it was meant to fix is still closed by the existing end-of-pipeline rescue pass.
    • Flipped collapse-loop virtualization (347a4343) back to opt-in (FISSION_COLLAPSE_LOOP=1) after it broke real switch-structuring by defaulting on; the feature itself is untouched, just not default yet.
    • Added a missing side-effect guard to a live-return-register recovery fallback (446dc4b9) that was synthesizing a return value for a register already consumed by an unrelated store before a genuine void return.
    • Gated fission-emulator's selfjit module to #[cfg(unix)] -- its executable-memory management is written directly against libc::mmap/mprotect, which don't exist on Windows, and nothing outside the module depends on it yet.
    • Cleared 8 pre-existing clippy -D warnings failures and 3 cargo-deny license rejections (BSL-1.0, NCSA -- both OSI-approved/FSF-Free, transitive via arboard's desktop clipboard support) that were also independently blocking the Fast Gate.

    Known issues¶

    • selfjit is not yet the emulator's default backend and cranelift-* has not been removed from the dependency tree — this release builds correctness evidence toward that switch but does not make it.
    • selfjit's differential harness reports (does not fail on) any real translation block using an opcode it doesn't yet cover; full-function coverage across the corpus is not yet complete.
    • .debug_line line-number extraction (landed in v0.1.6) still has no rendering consumer wired up.
